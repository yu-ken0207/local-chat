# 手機上動手做事（設計）

狀態：設計定稿前的討論版，還沒開始做（2026-10-29）。

## 1. 目標與範圍

**目標**：電腦上的模型決定要做什麼，手機負責動手（例如加行程、設提醒）。家人不看說明也能用；凡是會改東西的動作都先給人確認，做完可以復原。

**第一批能力**：看行事曆、加行程、設提醒，以及「拍照加行程」（拍通知單，AI 讀出日期後加進行事曆）。

**不做**：

| 不做的事 | 原因 |
|---|---|
| 點螢幕、操作別的 App | iOS 不准；ESP32＋AirPlay 的作法另開專案研究 |
| 讀檔、跑指令、改檔案 | 家人用不到，本地小模型叫工具常出錯，風險高 |
| AI 自己做「捷徑」 | 捷徑檔要 Mac 簽章，目前沒有 Mac |
| Android 版 | 使用者決定不做 |

**使用者看到的畫面**：見第 7 節。

**參考**：Claude Code 的做事機制（Agent SDK 公開文件，連結在第 17 節）。只照抄設計，不用 SDK 本身：SDK 只接 Claude 模型，我們用的是電腦上的本地模型。

## 2. 名詞

| 名詞 | 意思 |
|---|---|
| 工具 | 一個 AI 可以叫的動作，例如「加行程」 |
| 一輪 | 模型回一次話，加上執行它這次叫的工具 |
| 做事循環 | 一輪接一輪，直到模型不再叫工具、給出最後回答 |
| 確認卡 | 動手前請使用者確認的卡片，內容可以修改 |
| 清單卡 | 一次要做好幾件事時，把它們列在同一張卡上確認 |
| 動作紀錄 | 做過的每個動作（做了什麼、怎麼復原） |

## 3. 整體架構

| 角色 | 負責 |
|---|---|
| 手機 App | 工具清單、做事循環、審核、確認卡、真的去執行工具、動作紀錄與復原 |
| 小幫手 | 把工具清單與工具呼叫轉給後面的引擎（第 11 節） |
| 電腦上的模型 | 決定要不要叫工具、叫哪個、填什麼內容 |

流程：手機把對話和工具清單一起送到電腦；模型回覆要叫的工具；手機審核、必要時出確認卡、執行；結果放回對話再送一次；直到模型給出最後回答。

行事曆等資料只在手機和使用者自己的電腦之間傳，不經過任何雲端。

## 4. 工具怎麼定義（照 MCP 格式）

每個工具除了 MCP 的三個欄位（名稱、說明、輸入格式），再加上 MCP 的屬性標記和我們自己需要的欄位：

```ts
type PhoneTool = {
  name: string;                 // 給模型看的名稱，例如 create_event
  description: string;          // 給模型看的說明（英文，見第 16 節待決定 1）
  inputSchema: JSONSchema;      // 輸入格式，App 執行前會先驗證
  annotations: {
    readOnlyHint?: boolean;     // 只讀：可以直接做、可以同時做
    destructiveHint?: boolean;  // 會刪東西
    idempotentHint?: boolean;   // 重做一次也不會多出東西
  };
  requiresUserInteraction?: boolean; // 一定要人按，不能「以後不用問」（照 Claude Code）
  permission?: 'calendar' | 'reminders' | 'notifications'; // 要跟 iOS 要的權限
  label: string;                // 畫面上的白話名稱，例如「加行程」
  verb: string;                 // 確認卡按鈕上的動詞，例如「加入」「設提醒」
  describe(input): string;      // 確認卡上的一句話
  fillDefaults?(input): { input; guessed: string[] }; // 補上使用者沒說的欄位，回傳哪些是補的（確認卡標淡色）
  check?(input): string | null; // 執行前的 App 規則檢查，不通過回原因
  run(input): Promise<ToolResult>;
  undo?(result): Promise<void>; // 復原
};
```

**第一批工具（6 個以內，小模型工具越少越準）**

| 名稱 | 白話 | 種類 | 輸入 | 回傳 | 復原 |
|---|---|---|---|---|---|
| `list_calendars` | 看有哪些行事曆 | 只讀 | 無 | 名稱、能不能寫 | 不需要 |
| `list_events` | 看行事曆 | 只讀 | 開始、結束時間 | 最多 10 筆：標題、時間、行事曆名稱 | 不需要 |
| `create_event` | 加行程 | 會改東西 | 標題、開始、結束、整天、地點、備註、提前幾分鐘提醒、行事曆 | 行程編號 | 刪掉這個行程 |
| `create_reminder` | 加到「提醒事項」 | 會改東西 | 標題、時間、備註 | 提醒編號 | 刪掉這個提醒 |
| `ask_user` | 問使用者選擇題 | 問人 | 見第 8 節 | 使用者的選擇 | 不需要 |

「拍照加行程」不是一個工具：用現有的傳照片功能，模型看圖後叫 `create_event`。

現在的日期、星期、時間、時區不做成工具，每次都寫在系統提示詞裡（小模型常常不知道今天幾號）。

**回傳一律要短**：只帶必要欄位（不帶備註、參加者），筆數有上限，因為本地模型能記的內容有限。

## 5. 做事循環

1. 送出：對話內容、工具清單、系統提示詞（今天日期與時間、時區、回答語言、規則）。
2. 模型回覆：文字和要叫的工具都可能有。文字照常逐字顯示；叫工具時顯示「正在看行事曆…」。
3. 模型沒有叫工具：結束。
4. 有叫工具：每一個都先檢查名稱存在、輸入符合格式、通過 App 規則；再依第 6 節審核；然後執行。
   - 只讀的工具可以同時執行；會改東西的一個一個執行（照 Claude Code）。
   - 同一次回覆裡有兩個以上會改東西的動作，合成一張清單卡（第 9 節）。
5. 把每個工具的結果放回對話（`role: tool`），回到第 2 步。

**上限與結束**

| 結束方式 | 什麼時候 | 畫面上說 |
|---|---|---|
| 完成 | 模型不再叫工具 | 模型的回答，下面列出做了哪些事（可以復原） |
| 輪數用完 | 超過 5 輪（可以調） | 「做到一半停下來了」，列出已經做了的事 |
| 出錯 | 連線斷了、引擎出錯 | 沿用現在的錯誤說明，加上已經做了的事 |
| 使用者停止 | 按停止 | 停在目前這一步，已經做了的事保留、可以復原 |

**錯誤處理**

- 輸入格式不對、不符合 App 規則：把原因交回模型重填，同一個工具最多重試 2 次。
- iOS 權限被拒：告訴模型「使用者沒有給行事曆權限」，畫面給「打開設定」按鈕。
- 模型不支援工具（`/api/show` 的 capabilities 沒有 `tools`）：不送工具清單，照舊聊天。

## 6. 審核（四關，照 Claude Code 的順序簡化）

1. **禁止**：不在工具清單上的，或沒通過 App 規則（例如時間在過去、超過一年後），直接回絕，原因交回模型。
2. **一定要人按**：標 `requiresUserInteraction` 或 `destructiveHint` 的，每次都出確認卡，沒有「以後不用問」。
3. **只讀**：標 `readOnlyHint` 的直接做（第一次會跳 iOS 權限詢問）。
4. **其他會改東西的**：出確認卡。

Claude Code 還有允許／詢問／禁止規則、多種模式、AI 代審，對家人太複雜，第一版不做。

## 7. 確認卡與互動畫面

已決定（2026-10-29）：確認卡放在對話裡（不用從下面滑上來的面板）；AI 猜的欄位用淡色標出；按鈕用具體動詞。

**確認卡**

- **放在對話裡**：跟訊息一起排在對話中，留在對話紀錄裡；切走 App、甚至 App 被關掉，回來還在、還能按，按了就接著做。左邊對話清單上，有卡片還沒按的那一段標「等你確認」。
- **內容**：一句白話，例如「在 11/4（三）15:00–16:00 新增『帶小孩看牙醫』到『家庭』行事曆」；下面是可以改的欄位。
- **AI 猜的欄位標淡色**：使用者沒說、由 AI 或 App 補上的欄位（例如結束時間、加到哪個行事曆），用淡色顯示，提醒使用者看一下。怎麼知道哪些是猜的：模型只填使用者說到的欄位，其他欄位由工具的 `fillDefaults` 補上預設值（例如結束時間是開始後 1 小時、行事曆用預設的那個），補的欄位就是猜的。
- **按鈕用具體動詞**：
  - **加入／設提醒**（依工具的 `verb`）：執行，把結果交回模型。
  - **修改**：欄位變成可以編輯，改完再按動詞按鈕。交回模型的結果會寫明使用者改了什麼（Claude Code 不告訴模型，我們要告訴它，讓它的回答跟實際一致）。
  - **不要**：可以多打一句原因（選填）。原因交回模型，讓它換個做法或結束。
- **觸覺回饋**：按動詞按鈕和做完時各震一下。

**畫面示意**（照 App 現在的風格：`›` 是使用者，`•` 是 AI）

一句話加行程：
```
› 下週三下午三點帶小孩看牙醫

• 看了行事曆（那天有 1 個行程）            ⌄
  ┌ 加行程
  │ 11/4（三）15:00–16:00     （16:00 是猜的，淡色）
  │ 帶小孩看牙醫
  │ 加到：家庭・提前 30 分鐘提醒（猜的，淡色）
  └ [不要]   [修改]   [加入]
```
按「加入」之後：
```
• 已經加到「家庭」行事曆，會提前 30 分鐘提醒你。
  那天早上你還有「晨會」。
  ✓ 新增 1 個行程                          [復原]
```

拍照加行程（清單卡，第 9 節）：
```
› [照片：學校通知單] 幫我加到行事曆

• 通知單上有 3 個活動：
  ┌ 加 3 個行程到「家庭」
  │ ☑ 11/7（六）09:00   校慶運動會
  │ ☑ 11/13（五）18:30  親師座談會
  │ ☑ 11/20（五）整天    戶外教學
  └ [不要]   [修改]   [加入 3 個]
```

不確定就問（第 8 節）：
```
› 明天提醒我繳電費

• 明天幾點提醒你？
  ( 早上 9:00 )  ( 中午 12:00 )  ( 晚上 8:00 )  ( 其他… )
```

按「不要」並說要改成怎樣：
```
  要改成怎樣？（可以不填）
  │ 改成週四
  └                                  [送出]

• 好，改成 11/5（四）15:00。（接著出一張新的確認卡）
```

只是問，不出卡：
```
› 我這週有什麼行程？

• 看了行事曆（5 筆）                       ⌄
• 這週有 5 個行程：週一 9:00 晨會、週三……
```

**其他時候**

- **第一次用**：AI 說明要看行事曆才能加行程，接著跳 iOS 系統的權限詢問；按不允許，AI 說明做不到，並給「打開設定」按鈕。
- **按「復原」**：底下跳一行「已刪除『帶小孩看牙醫』」。
- **設定頁**：「AI 可以做的事」，行事曆、提醒事項各一個開關；下面是「做過的事」，每一筆都可以復原（第 10 節）。

## 8. 反問選擇題（`ask_user`）

照 Claude Code 的 AskUserQuestion，配合小模型縮小：

- 一次 1 題，2～4 個選項，最後固定多一個「其他（自己打字）」。
- 每個選項有短名稱和一句說明。
- 回給模型 `{ 問題: 選到的名稱 }`；自己打字就回打的內容。
- 系統提示詞要求模型「不確定就問，不要猜」，例如不知道要加到哪個行事曆。

## 9. 清單卡（一次做好幾件事）

Claude Code 用「規劃模式」先列步驟再動手。小模型不適合多一個模式，改成：

- 同一次回覆裡有 2 個以上會改東西的動作，App 自動合成一張清單卡，每一項可以取消勾選或修改，最後按一次動詞按鈕（例如「加入 3 個」）。
- 執行時顯示「正在加第 2 個行程（共 3 個）」。進度由 App 依照清單顯示，不靠模型自己維護待辦清單。

## 10. 動作紀錄與復原

- 每個執行過的會改東西的動作，都記下：工具、輸入、結果（例如行程編號）、時間、屬於哪段對話的哪則訊息、狀態。
- 狀態：等待確認／已拒絕／已完成／失敗／已復原。
- 回答下方顯示「已完成：新增 1 個行程」，旁邊有「復原」；按了就執行該工具的 `undo`。
- 刪掉對話不會刪掉已經加的行程，只刪紀錄。
- 重新產生回答時，已經做過的動作不會自動重做；新版本要做的動作一樣要再確認。
- 備份還原到新手機：紀錄跟著還原，但行程編號在新手機無效，所以不能復原。

**資料庫（第 5 版結構）**

- `messages.role` 增加 `tool`；新增欄位 `tool_calls`（模型要叫的工具，JSON）、`tool_name`（tool 訊息屬於哪個工具）。
- 新表 `actions`：一列一個動作，欄位見上面「記下」那一條，加上狀態。
- 工具訊息在畫面上收成一行「看了行事曆（3 筆）」，點開看細節。

## 11. 小幫手要改的

| 引擎 | 要做的事 |
|---|---|
| Ollama | 目前原樣轉送，工具清單、工具呼叫、`role: tool` 都會照樣過去；只需要補測試確認串流中的工具呼叫有完整傳到手機 |
| LM Studio、OpenAI 格式的伺服器 | `ChatRequest` 加 `tools`；`ChatMessage` 加 `tool_calls`、`tool_name`；工具清單翻成 OpenAI 格式（`type: function`）；串流回來的工具呼叫是一段一段的文字，要拼完整再轉成 Ollama 格式（arguments 是物件）；`role: tool` 訊息翻成 OpenAI 的 `tool_call_id` 形式（沒有編號就由小幫手產生） |
| 模型清單 | 非 Ollama 的模型補上「支援工具」的標記（LM Studio 有 `trained_for_tool_use`），App 才知道要不要送工具清單 |

## 12. 模型與提示詞

- 只對支援工具的模型開放。開發機上目前的 gemma4（e2b、e4b、12b、31b）和 qwen3:4b 都標示支援。
- 系統提示詞要有：今天日期、星期、現在時間、時區；回答語言；「不確定就用 ask_user」；「日期只能用使用者說的或照片上看到的，不要自己編」；做完用一句白話說做了什麼。
- 思考模式和工具可以一起開（Ollama 支援）。
- **題庫評測**：準備 20～30 句家人會說的話（例如「下週三下午三點帶小孩看牙醫」「明天早上提醒我繳電費」，以及幾張通知單照片），在各個模型上跑，看叫對工具的比例、填對時間的比例，用來決定預設模型和小模型要不要開放。

## 13. iOS 權限與 Expo Go

- 用 `expo-calendar`（行事曆和提醒事項都有），Expo Go 內建；用 `npx expo install` 安裝。
- 權限只在第一次用到時才跟 iOS 要，不在打開 App 時要。
- Expo Go 裡跳出的權限說明文字是 Expo Go 的，改不了；之後自己編 App 上架時，要在 `app.json` 寫我們自己的說明。
- 做事循環只在 App 開著時跑。中途切走 App：停在下一個確認卡或下一輪之前，回來再繼續。手機關掉也繼續跑，是另一項功能「回答在背景繼續跑」，之後再做。
- 設定頁加「AI 可以做的事」：每一類一個開關，加上「做過的事」清單（就是動作紀錄）。

## 14. 測試

- **單元測試**：做事循環（用假模型照劇本叫工具）、四關審核、輸入格式驗證、App 規則、復原、資料庫升級。
- **元件測試**：確認卡（動詞按鈕、修改、不要、猜的欄位標淡色）、清單卡、選擇題、App 被關掉後確認卡還在。
- **小幫手（Go）**：OpenAI 格式的工具翻譯、串流工具呼叫拼接、Ollama 原樣轉送。
- **題庫評測**：見第 12 節。
- **iPhone 實機**：驗收清單加一節「動手做事」。
